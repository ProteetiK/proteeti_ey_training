Q21. (5 marks) Explain the difference between a zero-shot, one-shot, and few-shot prompt. Using a classification task as your example, describe when you would choose few-shot over zero-shot, and what trade-offs you consider.
Answer:
In a zero-shot prompt, we provide only instructions and no examples, and the model relies only on its own internal training data. 
One-shot prompt is when we only provide a single example to the model, in addition to it being expected to use its own training. 
In Few-shot Prompting, we provide multiple examples to the model so it can learn from that as well. Multiple examples help the model notice patterns, edge cases, and labeling conventions.
Few-shot prompting is useful when the task is ambiguous or domain-specific. For example, if we have to classify an IT support ticket into custom categories such as "Software" "Hardware" or "Bug". Examples clarify what each category means and promotes output consistency for the model. However, for few-shot prompts, the prompt length is longer and hence more tokens are consumed and latency increases.

Day 12
Q22. (5 marks) Describe the end-to-end data flow in a LangChain + Azure AI Search RAG pipeline — from the user's question to the final generated answer. Identify ONE potential failure point at each stage and how you would mitigate it.
Answer:
In a LangChain + Azure AI Search RAG pipeline, the process begins when the user submits a query, which LangChain receives and preprocesses it. Here, a potential failure point is an ambiguous query, which can be mitigated through implementing query structure. 
Next, the query is converted into an embedding and sent to Azure AI Search for semantic or vector retrieval. Here, a failure can occur if the embedding model does not capture the query's meaning correctly, which can be mitigated by selecting a domain-appropriate embedding model and regularly evaluating retrieval quality. 
Azure AI Search then retrieves the most relevant documents from the indexed knowledge base. Here, a failure point is missing metadata, which can be mitigated through data quality checks and hybrid search methods. 
LangChain then assembles the retrieved documents into a prompt context. Here, a failure can occur if context dilution happens, which can be mitigated through reranking, filtering, and chunk-size optimization. 
The prompt is sent to the LLM, which generates the final answer. Here, a failure point is LLM hallucination, which can be mitigated by grounding responses strictly in retrieved content before returning the response to the user. 
Then finally, this answer is sent to the user as the output.

Q23. (5 marks) You are running a structured experiment comparing three LLMs on a Q&A task. Define FOUR metrics you would log for each run and explain what each metric tells you about model performance or suitability.
Answer: 
Four metrics to check for comparing multiple LLMs' performance are:
Answer Accuracy: Measures if the model's response is correct compared to a ground-truth answer. High accuracy indicates the model can reliably answer questions correctly. 
Response Latency: Measures the time taken from receiving the question to generating the final answer. This metric helps measure real-time turnabout time performance of each model, which is crucial for customer-facing apps.
Token Usage: Tracks the number of tokens consumed during inference. Since most LLM services charge by the token, this metric allows us to keep track of the mounting cost and adjust accordingly.
Hallucination Rate: Measures how often the model produces factually incorrect information. This metric is especially important for critical domains like healthcare and legal serious where incorrect information bears serious consequence.

Q25. (5 marks) Explain the concept of multi-model routing. Describe a real-world scenario where you would route between Claude, Azure OpenAI, and a HuggingFace model, justifying each routing decision with a technical or business reason.
Answer:
Multi-model routing is an architectural design where an orchestration layer dynamically selects the most appropriate AI model for a given request instead of sending all requests to a single model. The routing decision is usually based on task type, task complexity, latency requirements, or data sensitivity. The goal is to optimize performance, cost, and reliability while leveraging the strengths of different models.
For example, assuming the scenario where a single chatbot is responsible for receiving all user queries. 
Here, when a user asks for help with a complex or nuanced subject relating to the company policy, the chatbot might redirect it to the Claude model, which is good for extracting information from long files on compliance and returns a detailed, structured output.
If the customer asks for details steps on how to do something, for eg. Registering a product warrant, the chatbot might redirect this query to Azure OpenAI. This model is suited for this because it is capable of handling requests which require a strong backend scaffolding that is held by Azure, and it provides great security and availability, so that the customer is not left hanging at any time of the day.
If the customer then logs a ticket, a Hugging Face Model can be called on to classify it into the proper processing bucket. This models is cheaper than the others and hence can be more useful for bulk tasks, especially if the company sees a high traffic of such tickets.

from langchain_core.prompts import PromptTemplate
from langchain_core.documents import Document
from langchain_community.vectorstores import FAISS
from langchain_classic.chains import RetrievalQA
from langchain_community.embeddings import FakeEmbeddings
from langchain_community.llms.fake import FakeListLLM

def build_rag_chain():
    # Sample documents
    docs = [
        Document(
            page_content="LangChain is a framework for building LLM applications.",
            metadata={"chunk_id": 0}
        ),
        Document(
            page_content="Retrieval-Augmented Generation combines retrieval with generation.",
            metadata={"chunk_id": 1}
        ),
        Document(
            page_content="FAISS is commonly used as a vector store for similarity search.",
            metadata={"chunk_id": 2}
        )
    ]

    # In-memory vector store
    embeddings = FakeEmbeddings(size=128)
    vectorstore = FAISS.from_documents(docs, embeddings)

    # Retrieve top-2 chunks
    retriever = vectorstore.as_retriever(
        search_kwargs={"k": 2}
    )

    # Custom prompt
    qa_prompt = PromptTemplate(
        input_variables=["context", "question"],
        template="""
        Use the provided context to answer the question.

        Context:
        {context}

        Question:
        {question}

        Answer:
        """
    )

    # Mock LLM (replace with OpenAI(), ChatOpenAI(), etc.)
    llm = FakeListLLM(
        responses=[
            "LangChain supports Retrieval-Augmented Generation by combining retrieved documents with an LLM."
        ]
    )

    # RetrievalQA chain
    qa_chain = RetrievalQA.from_chain_type(
        llm=llm,
        retriever=retriever,
        chain_type="stuff",
        chain_type_kwargs={"prompt": qa_prompt},
        return_source_documents=True
    )

    return qa_chain

def ask_question(question):
    chain = build_rag_chain()

    result = chain({"query": question})

    # Extract source chunk indices
    source_indices = [
        doc.metadata["chunk_id"]
        for doc in result["source_documents"]
    ]

    return {
        "answer": result["result"],
        "source_chunk_indices": source_indices
    }

import time
import pandas as pd

def run_experiment(prompt, models, temperatures):
    """
    Args:
        prompt (str): Input prompt
        models (dict): {"model_name": model_object}
        temperatures (list): List of temperature values

    Returns:
        pandas.DataFrame
    """

    logs = []

    for model_name, model in models.items():
        for temperature in temperatures:

            start_time = time.time()

            # Example invocation
            response = model.invoke(
                prompt,
                temperature=temperature
            )

            latency_ms = (time.time() - start_time) * 1000

            # Approximate token count using whitespace split
            output_length = len(response.split())

            evaluation = (
                "pass"
                if output_length >= 50
                else "fail"
            )

            logs.append({
                "model_name": model_name,
                "temperature": temperature,
                "latency_ms": round(latency_ms, 2),
                "output_length_tokens": output_length,
                "evaluation": evaluation
            })

    return pd.DataFrame(logs)

            "story", "poem", "creative",
            "write", "generate", "imagine"
        ]

        analytical_keywords = [
            "analyze", "compare",
            "evaluate", "reason",
            "why", "tradeoff"
        ]

        if any(word in query_lower for word in creative_keywords):
            return "creative"

        if any(word in query_lower for word in analytical_keywords):
            return "analytical"

        return "simple"

    # -------------------------
    # Mock Providers
    # -------------------------

    def call_huggingface(self, query):
        """
        Mock HF call
        """
        return f"[HF] Answer for: {query}"

    def call_claude(self, query):
        """
        Mock Claude call
        """
        return f"[Claude] Analysis for: {query}"

    def call_azure_openai(self, query):
        """
        Mock Azure OpenAI call
        """
        return f"[Azure OpenAI] Creative response for: {query}"

    # -------------------------
    # Provider Dispatcher
    # -------------------------

    def invoke_provider(self, provider, query):

        if provider == "huggingface":
            return self.call_huggingface(query)

        elif provider == "claude":
            return self.call_claude(query)

        elif provider == "azure_openai":
            return self.call_azure_openai(query)

        raise ValueError(f"Unknown provider: {provider}")

    # -------------------------
    # Bonus: Cost Estimation
    # -------------------------

    def estimate_cost(self, provider, text):
        """
        Approximate token count via whitespace split
        """

        tokens = len(text.split())

        cost = (
            tokens / 1000
        ) * self.price_per_1k_tokens.get(provider, 0)

        return round(cost, 6)

    # -------------------------
    # Main Routing Logic
    # -------------------------

    def route(self, query):

        classification = self.classify_query(query)

        if classification == "simple":
            primary_provider = "huggingface"

        elif classification == "analytical":
            primary_provider = "claude"

        else:
            primary_provider = "azure_openai"

        failover = False

        try:
            response = self.invoke_provider(
                primary_provider,
                query
            )

            provider_used = primary_provider

        except Exception as e:

            failover = True

            secondary_provider = self.fallbacks[
                primary_provider
            ]

            logging.warning(
                f"Failover triggered: "
                f"{primary_provider} -> "
                f"{secondary_provider}"
            )

            response = self.invoke_provider(
                secondary_provider,
                query
            )

            provider_used = secondary_provider

        return {
            "query": query,
            "classified_as": classification,
            "provider_used": provider_used,
            "response": response,
            "failover": failover,
            "estimated_cost": self.estimate_cost(
                provider_used,
                response
            )
        }
